# Visual Expression Protocol

本协议吸收 `humanlayer/skills` 的 `show-me` 机制，但将它改造成 qiaomu-learning 的教学版本：每个视图都服务当前唯一认知问题，并在视图之后回到观察、预测、解释或迁移。

## 1. Smallest-view rule

先问“学习者现在需要看见什么关系”，再决定画什么。不要把“生成图片”当成可视化的同义词，也不要为了完整而把整章内容压成一张总图。

视图必须满足：

- 只承载当前一个认知目标；
- 只保留与该目标有关的节点、调用、文件、状态、箭头、数字或边界；
- 比纯文字更容易观察，或能让学习者操作一个明确变量；
- 结论不能被标题、颜色、箭头或答案标签提前泄露；
- 旁边附一句等价文字说明，视图失效时仍能继续学习。

## 2. Information-shape router

| 当前信息形态 | 首选视图 | 典型问题 |
|---|---|---|
| 规则、条件、算法 | 伪代码 | 哪个条件先判断？ |
| 函数调用、事件顺序 | 调用树/调用栈 | 哪一步触发了下一步？ |
| 页面、组件、状态边界 | 组件树 | 哪个组件拥有这个状态？ |
| 文件职责、重构范围 | 浅文件树 | 哪个目录应该负责这件事？ |
| 因果、交互、数据流 | Mermaid 流程/时序图 | 哪条箭头代表输入到输出？ |
| 前后版本、局部改动 | diff | 哪一笔改变了行为？ |
| 空间、几何、运动 | 确定性草图/坐标图 | 哪个点、方向或距离发生变化？ |
| 多层抽象映射 | 聚焦 HTML 或 Codex 生图 | 中间哪一层把输入变成输出？ |

如果一种简单视图已经足够，不升级到 HTML 或生图。多个视图只有在它们分别回答不同且连续的学习问题时才允许出现；一轮默认只展示一个主视图。

## 3. Progressive reveal

视图像黑板一样累积：

1. 先放起点、输入或已知条件；
2. 下一轮只增加一个关键节点、箭头、状态或变化；
3. 让学习者先观察，再命名关系；
4. 最后才补形式化术语、完整代码或结论。

如果需要展示前后差异，用 diff 保留上下文，但只标出当前学习台阶的局部变化。不要用完整重写冒充渐进推导。

## 4. Format contracts

### Pseudocode

用于规则和算法。变量名使用学习者已经见过的词；每个分支只表达一个判断，不夹带实现细节。问题聚焦“哪个条件决定下一步”。

### Tree

用于调用、组件和文件职责。树保持浅层，只展开当前问题需要的两到三层；节点可以附状态或归属，但不堆文件名和无关依赖。

### Mermaid

用于流程、时序、交互和数据流。箭头方向必须可核验；节点标签短；不把 Mermaid 当作事实来源，材料不清时标记未知。图后提供文字替代。

### Diff

用于解释“改变了什么”。保留足够上下文看出所有权和顺序，只修改当前相关的几行；新增、删除和保持部分要能被初学者看懂。

### Focused HTML

用于需要滑动、切换、拖动、前后对比或重复练习的概念。默认单文件、内联 CSS/JS、离线可打开；只展示当前台阶，不能把静态选项分支伪装成理解自然语言。生成前说明页面展示什么、暂不展示什么，生成后通过 `scripts/audit_webpage.py` 做源码审计。

## 5. Teacher loop after a view

视图不是讲解结束，而是下一次推理的输入：

```text
短反馈 → 主视图 → 等价文字替代 → 一个观察/预测/解释/迁移问题
```

不要用“看懂了吗？”收尾。优先问图上能直接回答的一个动作，例如“哪个节点先收到输入”“这条箭头改变后谁受影响”“新增的这一行把什么条件分开”。

## 6. Failure and accessibility

- Mermaid、HTML 或图片不可用时，退回 ASCII、表格、伪代码或文字关系；不重复盲试。
- 颜色不是唯一编码；用位置、形状、标签、线型和文字共同表达差异。
- 生成图中的数值、坐标、方向和标签必须由文字或确定性表达复核。
- 视图不能包含未授权的私人材料、完整受版权保护页面或会泄露答案的装饰文字。
