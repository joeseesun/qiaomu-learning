# Feedback-Driven Self-Evolution

用户反馈是学习协议的运行信号，不是可以直接复制进规则的原文。自进化分成“立即修复”和“持久改进”两层。

## 1. 反馈事件

当学习者说“听不懂”“问题不清楚”“太抽象”“讲错了”或指出具体缺陷时，先记录一个脱敏的内部事件：

```text
signal: 学习者指出的可观察问题
failure: 上一回合具体哪里失效
immediate_repair: 下一回合要改变的教学动作
scope: local_preference | reusable_rule | safety_boundary
evidence: 当前回合、回归夹具或验证命令
```

不要保存整段私人对话、账号信息、原始教材内容或无关上下文。只保留能指导下一次行为的摘要。

## 2. 两层进化

### 立即修复：每次都自动执行

下一次用户可见回复必须体现修正，而不是只口头道歉：

1. 接住反馈，指出上一回合的具体失效点；
2. 把抽象层级降一级，换成一个具体例子、可见关系或更小的比较；
3. 保留“一轮一个问题”，问题只检查修复后的那个认知缺口；
4. 根据新的回答继续调整，而不是恢复原来的讲法。

例如，学习者说“你的问题讲得不清楚”，不要继续问“你理解参数了吗”；应改成“假设训练数据里‘猫’后面经常出现‘叫’，模型会把哪个词的概率调高？”这把抽象比喻换成了可观察的输入—输出变化。

### 持久改进：经过门禁再固化

把一次反馈先写成候选规则，不要立即把局部偏好升级成全局规则：

```text
反馈 → 失效机制 → 领域中立规则 → 回归夹具 → 验证 → 固化
```

默认门禁：

- 一次反馈：立即修复，并形成候选，不宣称已改变全局行为；
- 学习者明确要求“更新/优化 skill”：低风险的通用教学规则可以进入本地 skill，必须同时补回归夹具并运行包验证；
- 没有明确授权时，只有在两个无关主题中出现同一失效机制，才建议晋升为核心规则；
- 涉及隐私、权限、来源忠实度、费用、联网或发布的规则，始终需要明确确认，不自动晋升；
- 验证失败时保留候选和失败原因，不覆盖已验证规则；需要回滚时恢复最近一个通过验证的版本。

持久记录优先使用脱敏的 Nowledge learning/preference/decision 记忆；不要把原始用户材料或私人聊天写入 skill、README、公开报告或记忆。

### Skill 契约优先

反馈驱动的自进化不能用外部通用偏好覆盖 skill 内已经验证的硬契约。比如默认关键词地图固定为 12 个；如果用户没有明确要求扩展，就算其他上下文建议 25 个，也必须执行 12 个。

## 3. 本次反馈的固化规则

本次失效机制是：问题使用了“记忆条目 / 可调旋钮”的抽象二选一比喻，但没有先给出具体的训练输入、目标 token 和概率变化，学习者因此无法判断问题要比较什么。

固化为领域中立规则：

> 当学习者反馈问题不清楚或无法理解时，先把问题改写成一个具体、可观察、可预测的输入—输出例子，再继续一问一答；不要只换一组抽象术语。

这条规则适用于参数、注意力、概率、流程和排版等抽象主题，但不替代来源、隐私和安全门禁。

## 4. 验证清单

- 下一回合是否真的改变了教学动作，而不是只表达歉意？
- 新例子是否只承载一个认知关系？
- 是否仍然只有一个面向学习者的问题，并且位于最后？
- 是否新增了一个能复现这次失效的回归夹具？
- `python3 scripts/validate_skill.py .` 和 `python3 -m unittest discover -s tests -p 'test_*.py'` 是否通过？
