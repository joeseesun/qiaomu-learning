# Story And Visual Learning

故事和图像是认知支架，不是每轮必加的装饰。先判断当前缺口是否真的由“缺少具体模型或可见关系”造成。

## 1. 模态选择

| 当前困难 | 优先支架 |
|---|---|
| 忘了材料中的术语或事实 | 自由回忆或位置线索 |
| 不理解人物目标、激励、制度约束 | 具名人物情境 |
| 不理解先后顺序或状态变化 | 流程图、分镜或时间线 |
| 不理解因果链或一个变量影响多个结果 | 因果图或受控对比图 |
| 不理解空间、几何、组成或视角 | 结构图或空间示意图 |
| 不理解曲线形状、方向或比较 | 经核验的图表或简化坐标图 |
| 只是觉得内容枯燥 | 先改问题，不自动生图 |

一张图若只是重复文字、添加气氛或显得“高级”，就不应生成。

## 2. 具名人物情境

情境使用这个最小结构：

```text
<名字> 是 <相关角色>。
他/她要完成 <具体目标>，但受到 <一个关键约束>。
他/她做了 <一个选择或动作>，于是出现 <可观察结果>。
```

示例骨架：

> 类比情境（虚构）：Maya 是一名债券组合经理。老板要求她降低组合对利率上升的敏感度，但不能大幅牺牲收益。她在两只票息相近、到期时间不同的债券之间做选择。

故事后只问一个能暴露机制的问题。不要同时要求判断、解释和计算。学习者回答后，再明确写出故事映射：谁对应哪个变量，哪个行动对应哪个机制，以及类比在哪个边界失效。

### 故事质量检查

- 人名、角色、目标和约束都服务概念；无无关背景。
- 故事不包含真实个人数据，不伪装成真实案例或研究证据。
- 角色不依赖性别、地域、职业或文化刻板印象。
- 情节没有把正确答案直接写进角色台词。
- 故事控制在 1–3 句；需要更长才能成立时，优先换支架。

## 3. 图像生成门

同时满足以下条件才调用内置生图：

1. 当前问题依赖空间、因果、顺序、几何、曲线或多组件关系；
2. 纯文字会显著增加工作记忆负担，或现有材料没有合适图；
3. 图像可以围绕一个问题设计，而不是一次展示整章答案；
4. 当前平台有可用且获授权的图像生成能力；
5. 能在使用前检查关键关系，并提供文字替代。

若已有经授权、可读且准确的原图，优先使用原图。精确坐标、量化曲线、解剖结构、安全流程和证据型图像优先使用确定性绘图或可信来源，不依赖生成模型猜细节。

## 4. Codex / OpenAI 适配

在提供内置图像生成工具的 Codex/OpenAI 环境：

1. 先写出图的学习目标和唯一问题。
2. 调用可用的内置图像生成能力；一轮只生成一张核心图，除非平台工作流本身要求候选。
3. 提示词只包含必要结构，不带用户无关隐私或整页受版权保护材料。
4. 工具返回后检查方向、层级、数量、文字、坐标和因果箭头；不把漂亮当准确。
5. 在用户可见回复中给一段简短文字替代，并把唯一学习问题放在最后。

如果调用需要付费、新账号或超出当前授权，把是否调用作为当轮唯一问题。工具失败、不可用或结果不可靠时，明确降级为文字、ASCII、小表格或基于原图的描述，不重复盲试。

## 5. 问题承载型提示词

可使用以下平台中立骨架，按工具要求改写：

```text
创建一张用于主动推导的教学示意图，而不是答案海报。
主题：<概念>
只展示：<学习者需要观察的 2–5 个元素>
关系：<空间 / 因果 / 顺序 / 几何 / 曲线关系>
当前问题：<唯一问题>
限制：不写结论，不标出正确选项，不加入装饰，不使用无关文字；标签简短且可核验。
风格：清晰、高对比、适合当前语言和阅读水平。
```

图像中的标签若可能泄露答案，就改用 A/B、起点/终点或中性符号，让学习者先说出关系。

## 6. 视觉后的学习闭环

不要用“看懂了吗”收尾。按顺序只取当前所需的一步：

1. 观察：让学习者说出图中一个可见变化；
2. 预测：改变一个条件，让学习者预测结果；
3. 命名：学习者推导后再给概念名称；
4. 迁移：去掉图或换一个表面情境，让学习者复述机制。

视觉不是掌握证据。学习者仍需用自己的话解释，并在没有同一张图的情况下完成一次迁移。

## 7. 无障碍、隐私与版权

- 每张教学图提供等价文字描述；颜色不是唯一编码，关键差异同时用位置、形状或标签表达。
- 不把视力、阅读障碍或低带宽用户锁在图像路径里。
- 不把人脸、姓名、账号、地址、成绩、健康信息或完整教材页送入图像工具，除非确有必要、获授权且平台政策允许。
- 用户材料只抽象成教学结构；不重制受版权保护的整页版式或角色形象。
- 生成内容明确是教学示意，不冒充照片、实验记录、市场数据或权威证据。
