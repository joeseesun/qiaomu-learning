# Story And Visual Learning

故事和图像是认知支架，不是每轮必加的装饰。先判断当前缺口是否真的由“缺少具体模型或可见关系”造成。

## 1. 模态选择

| 当前困难 | 优先支架 |
|---|---|
| 忘了材料中的术语或事实 | 自由回忆或位置线索 |
| 不理解人物目标、激励、制度约束 | 具名人物情境 |
| 不理解先后顺序或状态变化 | 流程图、分镜或时间线 |
| 不理解因果链或一个变量影响多个结果 | 因果图或受控对比图 |
| 不理解空间、几何、组成或视角 | 结构图或空间示意图 |
| 不理解曲线形状、方向、斜率、极限或面积比较 | 经核验的图表或简化坐标图 |
| 不理解两层以上的抽象映射、向量、矩阵、波形或模型架构 | Codex 内置生图的当前帧 + 文字校验 |
| 只是觉得内容枯燥 | 改成真人教师节奏，并在结构适合时渐进板书 |

一张图若只是重复文字、添加气氛或显得“高级”，就不应生成。

## 2. 主动视觉锚点与恢复协议

视觉不必等到学习者明确说“太抽象”才出现。首次进入运动、变化率、曲线、斜率、极限、导数、积分面积或累积量等微积分台阶时，先提供一个小型视觉锚点；优先用确定性的坐标草图、ASCII、表格或时间线。它只服务当前台阶，学习者完成一个观察问题后，下一台阶重新判断，不能扩大成每轮生图。

学习者说“枯燥”时，不要只增加图片数量。读取 [Blackboard Teaching](blackboard-teaching.md)，把当前解释改成“接住上一句 → 画下一笔 → 解释一个连接 → 问一个观察题”；图示应当逐层累积，而不是一次给出完整答案。

例如，讲平均速度到瞬时速度时，先展示“宽时间窗口 → 窄时间窗口”的表格或时间线，再引入 `h`；讲导数时，先展示两点连线逐渐贴近曲线方向，再命名割线和切线。不要在学习者还没看见关系时直接丢出极限公式。

学习者明确求图，或反馈“太抽象、想象不出来、还是不理解”，且当前认知台阶能表示为空间位置、相对运动、几何关系、先后流程、因果链、状态变化或曲线时，**下一次用户可见回复必须立即换模态**；不要继续改写同一段口头解释。

如果台阶包含两层以上相互作用的抽象映射，例如“角度 → 波形 → 数字”、向量加法、注意力矩阵或 Transformer 模块，且 Codex 内置生图可用，优先直接调用内置生图，不要把 ASCII 当成最终视觉。学习者明确说“画得太抽象”或要求 Codex 生图时，这条优先级更高。

- 空间、相对运动、几何、流程等强视觉结构，如果关系精确且简单，优先使用可控的确定性图示；如果包含多层映射或抽象结构，优先用 Codex 内置生图建立直觉，再用文字、公式或确定性小图校验。
- 生成图不只适合人物情境，也适合复杂结构的第一直觉层；使用前必须核验关键关系、方向、数量、标签和因果箭头，不可靠就把错误关系从教学链中剔除并用确定性图示替代。
- 工具不可用或生成失败时，当轮直接降级为文本图示，不重复盲试。
- 图后给出等价文字描述，再把台阶降到一个可观察问题，例如“哪个先动”“方向怎样变”或“哪条连接发生变化”，并把它放在最后。
- 若采用渐进板书，保留上一帧，只新增一个点、线、箭头、区域或公式变形，并让问题只指向这次新增内容。
- 图中不得直接标出结论、正确选项或答案箭头；优先用 A/B、起点/终点等中性标记，让学习者先观察和推导。

## 3. 具名人物情境

情境使用这个最小结构：

```text
<名字> 是 <相关角色>。
他/她要完成 <具体目标>，但受到 <一个关键约束>。
他/她做了 <一个选择或动作>，于是出现 <可观察结果>。
```

示例骨架：

> 类比情境（虚构）：Maya 是一名债券组合经理。老板要求她降低组合对利率上升的敏感度，但不能大幅牺牲收益。她在两只票息相近、到期时间不同的债券之间做选择。

故事后只问一个能暴露机制的问题。不要同时要求判断、解释和计算。学习者回答后，再明确写出故事映射：谁对应哪个变量，哪个行动对应哪个机制，以及类比在哪个边界失效。

### 故事质量检查

- 人名、角色、目标和约束都服务概念；无无关背景。
- 故事不包含真实个人数据，不伪装成真实案例或研究证据。
- 角色不依赖性别、地域、职业或文化刻板印象。
- 情节没有把正确答案直接写进角色台词。
- 故事控制在 1–3 句；需要更长才能成立时，优先换支架。

## 4. 图像生成门

同时满足以下条件才调用内置生图；若学习者明确要求 Codex 生图，或反馈 ASCII/文字太抽象，直接视为满足第 1、2 项：

1. 当前问题依赖空间、因果、顺序、几何、曲线、多组件关系，或两层以上的抽象映射；
2. 纯文字、ASCII 或静态公式会显著增加工作记忆负担，或学习者已明确表示它们太抽象；
3. 图像可以围绕一个问题设计，而不是一次展示整章答案；
4. 当前平台有可用且获授权的图像生成能力；
5. 能在使用前检查关键关系，并提供文字替代。

若已有经授权、可读且准确的原图，优先使用原图。精确坐标、量化曲线、解剖结构、安全流程和证据型图像优先使用确定性绘图或可信来源，不依赖生成模型猜细节。

## 5. Codex / OpenAI 适配

在提供内置图像生成工具的 Codex/OpenAI 环境：

1. 先写出图的学习目标和唯一问题。
2. 调用可用的内置图像生成能力；一轮只生成一张核心图，除非平台工作流本身要求候选。
3. 提示词只包含必要结构，不带用户无关隐私或整页受版权保护材料。
4. 工具返回后检查方向、层级、数量、文字、坐标和因果箭头；不把漂亮当准确。
5. 在用户可见回复中给一段简短文字替代，并把唯一学习问题放在最后。

如果调用需要付费、新账号或超出当前授权，把是否调用作为当轮唯一问题。工具失败、不可用或结果不可靠时，明确降级为文字、ASCII、小表格或基于原图的描述，不重复盲试。

## 6. 问题承载型提示词

可使用以下平台中立骨架，按工具要求改写：

```text
创建一张用于主动推导的教学示意图，而不是答案海报。
主题：<概念>
只展示：<学习者需要观察的 2–5 个元素>
关系：<空间 / 因果 / 顺序 / 几何 / 曲线关系>
当前问题：<唯一问题>
限制：不写结论，不标出正确选项，不加入装饰，不使用无关文字；标签简短且可核验。
风格：清晰、高对比、适合当前语言和阅读水平。
```

图像中的标签若可能泄露答案，就改用 A/B、起点/终点或中性符号，让学习者先说出关系。

## 7. 视觉后的学习闭环

不要用“看懂了吗”收尾。按顺序只取当前所需的一步：

1. 观察：让学习者说出图中一个可见变化；
2. 预测：改变一个条件，让学习者预测结果；
3. 命名：学习者推导后再给概念名称；
4. 迁移：去掉图或换一个表面情境，让学习者复述机制。

视觉不是掌握证据。学习者仍需用自己的话解释，并在没有同一张图的情况下完成一次迁移。

## 8. 无障碍、隐私与版权

- 每张教学图提供等价文字描述；颜色不是唯一编码，关键差异同时用位置、形状或标签表达。
- 不把视力、阅读障碍或低带宽用户锁在图像路径里。
- 不把人脸、姓名、账号、地址、成绩、健康信息或完整教材页送入图像工具，除非确有必要、获授权且平台政策允许。
- 用户材料只抽象成教学结构；不重制受版权保护的整页版式或角色形象。
- 生成内容明确是教学示意，不冒充照片、实验记录、市场数据或权威证据。
